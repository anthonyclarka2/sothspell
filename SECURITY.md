# Security Policy

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting on
<https://github.com/anthonyclarka2/sothspell> (Security → Report a
vulnerability). Do not open a public issue for an unfixed vulnerability. Include
the affected version/commit, a reproduction, and the impact you believe it has.
We aim to acknowledge reports within a few days.

## Supported versions

The `main` branch is the supported version. This is a local-first, single-user
application; there are no hosted deployments to patch separately.

## Security posture

- **Local-first, loopback by default.** The API binds `127.0.0.1`. Binding
  another host prints a warning; the API has no authentication, so remote
  exposure must sit behind a trusted proxy that authenticates and terminates
  TLS.
- **Request boundary.** Every request validates `Host` when present (loopback,
  IP literals, or the configured public host) so DNS rebinding cannot make a
  malicious page same-origin. Mutating requests validate `Origin` when present,
  refuse `Sec-Fetch-Site: cross-site`, and require `application/json` for a
  body. A cross-site page cannot reach a write handler, even with a
  `text/plain` form post.
- **Read-only projects.** Analysis, authoring, playback, import, and review
  never write inside a project. All artifacts live under `SOTHSPELL_HOME`.
- **Path containment.** Source reads resolve the project root and the target
  through `realpath`, reject absolute paths, parent traversal, NUL bytes, and
  symlinks that leave the root. Tour ids are validated against a path-safe
  pattern before any directory join, so a decoded `%2F` or `..` cannot escape
  `projects/`.
- **Private local state.** SQLite databases, their WAL sidecars, and the
  directory that holds them are created and re-chmodded owner-only (`0600` /
  `0700`). Profile and secret files are `0600` with atomic writes.
- **Secret handling.** Provider keys live in `$SOTHSPELL_HOME/config/secrets.json`
  (mode `0600`, atomic writes) or in server environment variables. They are
  write-only through the API: listings return a `secretRef` and `hasSecret`
  flag, never a value. Keys are never logged, embedded in tours, or sent to the
  browser.
- **Provider calls are server-side.** Authoring, translation, in-tour
  questions, and narration run in the API process; the browser only talks to
  `/api/*` on the same origin.
- **Import sandbox.** Public GitHub imports use `execFile` argument arrays (no
  shell), a host allowlist, depth 1, single branch, no tags/submodules/LFS/
  hooks, a scrubbed `GIT_*` environment, a timeout, size ceilings, and a
  read-only clone under `SOTHSPELL_HOME`. Project code never runs.
- **Accounts.** GitHub OAuth uses PKCE and signed state; sessions are
  server-side rows with httpOnly, SameSite=Lax cookies, rotation, expiry, and
  revocation. `SOTHSPELL_SESSION_SECRET` must be at least 32 characters; a
  shorter or empty value is treated as unset and an ephemeral 256-bit key is
  used instead. OAuth tokens never leave the server.
- **Rendering.** The model produces structured JSON, never HTML or SVG.
  Highlighted code is generated by Shiki with every token escaped before it is
  wrapped; no user or model string is passed to `dangerouslySetInnerHTML`
  unescaped. In-tour answers render as text. The embed player treats a remotely
  loaded tour's `anchor.html` as untrusted: it sanitizes to escaped text plus
  `<span style>` with an allowlisted style property set, restricts tour URLs to
  allowed origins, and the exported iframe page sets a restrictive CSP.
- **Harness children.** Claude Code and Codex child processes receive an
  allowlisted environment (PATH, HOME, locale, and their own provider
  variables) instead of the full server environment, so unrelated tokens are
  not inherited.
- **Data access.** SQLite statements are prepared with bound parameters;
  identifiers never come from request input. There is no `eval`, no
  `new Function`, and no shell execution of user input.
- **No telemetry.** There is no analytics, remote logging, or hidden network
  call.

## Secret scanning and dependency checks

```bash
pnpm check:secrets          # scans every tracked file for credential shapes
pnpm audit --prod           # runtime dependency advisories
```

Both run in CI. The working tree, the full git history, and the lockfile were
scanned on 2026-10-18 with no credentials found.

## Dependency advisories

`pnpm audit --prod` reports **no known vulnerabilities**. The analyzer
enumerates files with a local directory walker instead of `fast-glob`, which
removed the transitive `braces` advisory from the runtime path.

The full audit (including dev dependencies) still lists four advisories reached
only through `@opencode/*`'s transitive tree: `braces` (high, via
`@parcel/watcher`), `@modelcontextprotocol/client` (high, MCP OAuth client),
`sprintf-js` (moderate), and `@ai-sdk/provider-utils` (low). Those packages are
devDependencies of the OpenCode plugin used for embedded-host tests; they are
not part of the shipped web app, CLI, API, or plugin runtime.

## Accepted risks and limits

- **No API authentication.** The local API trusts the machine's user. A local
  process can call it. A web page cannot: `Host`, `Origin`, `Sec-Fetch-Site`,
  and the JSON content-type requirement block cross-site writes, including
  `text/plain` form posts and DNS-rebinding attempts. A malicious local program
  is outside the threat model.
- **Arbitrary local paths.** `/api/projects/inspect` and `/api/authoring`
  accept any path that is a git repository. That is the feature; it stays
  loopback-only.
- **User-configured provider base URLs.** A connection profile can point at any
  HTTP(S) base URL, so the settings "test" button can reach a URL the user
  typed. It is a deliberate, local, user-initiated request. An attacker who
  cannot write a profile cannot redirect a stored key.
- **Embed tour URLs.** The embed player accepts tour URLs from the page origin
  by default and from an explicit `tour-origins` allowlist; the iframe page's
  CSP limits `connect-src` to its own origin. A host that allows a third-party
  tour origin accepts that origin's content, though its HTML is sanitized.
- **Model output is untrusted.** It is schema-validated, bounded, repaired at
  most a fixed number of times, and rendered as structured content; it is never
  executed.
- **No rate limiting.** A single-user local server does not throttle provider
  calls; provider limits and the user's own choices bound cost.
- **Ephemeral session secret.** Without a 32+ character
  `SOTHSPELL_SESSION_SECRET`, sessions reset on restart; the account page
  reports the ephemeral state.

## Operator checklist

1. Keep the default loopback bind; if remote access is required, put the app
   behind an authenticating reverse proxy with TLS.
2. Set `SOTHSPELL_SESSION_SECRET` to a random value of at least 32 characters.
3. Keep provider keys out of the repository; use `$SOTHSPELL_HOME` or the
   server environment.
4. Run `pnpm check:secrets` and `pnpm audit --prod` before publishing a fork.
5. Treat imported repositories as untrusted input: they are analyzed read-only
   and never executed.
