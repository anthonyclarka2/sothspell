# "API: serve bounded canvas symbol definitions and relations"

"The browser must not read project files or receive whole-file payloads. The
canvas needs one bounded endpoint that resolves a symbol definition, incoming
relations, or outgoing relations from the snapshot plus the local source root,
with safe excerpts and honest relation kinds."

---

## Update 1 — plan (2026-10-21)

"Planned as Phase 18 Wave 3 in `plans/PHASE-18.md`. Add
`GET /api/tours/:tourId/canvas/symbol?symbolId=<url-encoded-id>` and
`GET .../relations?symbolId=<url-encoded-id>&direction=incoming|outgoing&limit=8&offset=0`.
Symbol IDs contain `:` and `/`, so they travel as query values, not path
segments. Resolve the source root from `projects/<slug>/project.json` or the
configured golden root. Load `projects/<slug>/snapshot.json` only
when its `analyzerVersion` matches; otherwise re-analyze once and cache by
canonical root, fingerprint, and version. Check `snapshot.files[].redacted`
before excerpting and return 409 for a redacted path. Harden the existing source
route against the same gap and thread `tourId` through the code-page link,
search schema, and `fetchAnchor` so the route reads the correct project root.
Validate tour, symbol, direction, limit, and offset;
cap containers and excerpt bytes; return 404 for unknown symbols and 409 when
relations or source are unavailable. Test valid, missing, stale, malformed,
oversized, redacted, and path-escape requests."

---

## Fix

"Shipped with Phase 18 (commit `e378e86`, merge `169914a`, plus `c1a61e1`).
The route serves definitions, incoming, and outgoing relations with 8-container
and 64 KiB caps, relation kind/confidence, identifier targets, redaction checks,
and 404/409/400 mapping. Project roots resolve from `project.json`, with the
golden Bunbun fallback. The source route accepts `tourId` and refuses redacted
files. Tests cover the full matrix."
