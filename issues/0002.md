# "Canvas: add the opt-in view without duplicating playback"

"A viewer needs to switch between the current Stage and the canvas without
losing the beat, playback position, narration mode, or run progress. A separate
route would duplicate the player's clock, narration, and run persistence. The
canvas should be a view of the existing player route."

---

## Update 1 — plan (2026-10-21)

"Planned as Phase 17 Wave 3 in `plans/PHASE-17.md`. Use `?view=canvas` on the
existing `/t/$tourId/$beatId` route, a Stage/Canvas switch, and one `CanvasView`
that receives the current tour and beat. The player keeps the playback engine,
narration, transport, and run store. Add a round-trip browser test."

---

## Fix

"Shipped with Phase 17 (commit `be02945`, merge `6ec128b`). `?view=canvas` is a
validated search parameter on the player route; the Stage/Canvas switch preserves
the beat, playback, narration, and run state. The compact fallback below 768 px
shows the Stage and the Phase 19 note."
