# Phase 2 — Repository Intelligence

**Status: complete (2026-10-17).** Depends on: Phase 1 (schema, source access,
golden tour).

**Deliverable:** a read-only project registration and snapshot system, a
TypeScript/JavaScript symbol graph built on `oxc-parser`, a deterministic project
brief, an incremental cache, and a CLI. Bunbun is the acceptance project.

## Goal

Turn a local repository into evidence the authoring pipeline can trust. The
analyzer must answer: what files exist, what they contain, which symbols they
define, how modules depend on each other, what the project says about itself,
and what changed since the last snapshot.

This phase does not call a model. It produces the facts.

## Why this order

- The authoring pipeline cannot cite code it cannot resolve.
- The compiler needs stable symbol IDs and content hashes.
- The Bunbun golden tour needs real anchors beyond the hand-authored excerpts.
- The read-only trust model must be implemented before any model sees source.

## Scope

### In scope

- Local project registration with an allowlist and path containment.
- Ignore rules, binary detection, size limits, and secret redaction.
- Git revision metadata (commit, branch, dirty state).
- A file manifest with hashes and language detection.
- TypeScript/JavaScript parsing and symbol extraction with `oxc-parser`.
- Module dependency graph and approximate reference graph.
- NestJS, Prisma, and package-manifest enrichment.
- A deterministic project brief and module clusters.
- Snapshot caching and incremental re-analysis.
- A CLI: `sothspell analyze <path> --json`.
- Bunbun acceptance tests.

### Out of scope

- Model calls.
- Python, Go, Rust, Java, or C/C++ analyzers.
- Full type checking or semantic resolution.
- Runtime tracing or execution.
- GitHub cloning or hosted repositories.
- Writes to the target repository.

## Decisions

1. **Read-only is a hard invariant.** The analyzer opens files with read
   access, never writes, and never executes project code or package scripts.
2. **The snapshot is content-addressed.** Snapshot ID = hash of canonical root
   identity, revision, dirty file hashes, analyzer version, and ignore-rule
   version. Two identical analyses produce the same ID.
3. **Symbols are the primary anchor.** File paths and line ranges are secondary.
4. **Syntax, not types.** `oxc-parser` gives fast, TS 7-independent syntax. The
   analyzer does not attempt full type inference; it records decorators, imports,
   exports, and lexical structure.
5. **Enrichment is explicit.** NestJS and Prisma are adapters over the generic
   symbol graph, not special cases baked into it. Adding another framework
   should be a new enrichment module.
6. **The project brief is deterministic.** It is assembled from manifests,
   docs, directory structure, and graph statistics. The LLM sees it in Phase 3;
   it is not generated by an LLM.
7. **Target repository state stays out of shareable artifacts.** The snapshot
   stores a root fingerprint for local resolution, not an absolute path in the
   tour.

## Waves

### Wave 0 — Project registration and safety

1. `ProjectSource` interface:
   ```ts
   interface ProjectSource {
     canonicalRoot: string;
     fingerprint: string;
     readFile(relativePath: string): Promise<string>;
     listFiles(): Promise<FileEntry[]>;
   }
   ```
2. Root validation:
   - resolve `realpath`;
   - require the root to be under `SOTHSPELL_ALLOWED_ROOTS`;
   - reject the filesystem root, the home directory itself, and paths with
     control characters;
   - detect a Git worktree; record the canonical checkout.
3. Path safety:
   - reject absolute paths and `..`;
   - resolve symlinks and require containment;
   - reject devices, sockets, FIFOs, and files above the size cap;
   - deny `.git`, `node_modules`, build output, `.env*`, private keys, and
     configured deny globs.
4. Secret redaction:
   - detect common token/key patterns (AWS, GitHub, OpenAI, Anthropic, generic
     PEM blocks, high-entropy assignments);
   - never include a matching line in a model context or log;
   - mark the file as redacted and record a warning.
5. Tests with temp directories:
   - traversal, symlink escape, and absolute path fail;
   - secret files are skipped;
   - a redacted excerpt is refused;
   - a normal file is read exactly.

### Wave 1 — Snapshot model

1. Define `ProjectSnapshot`:
   ```ts
   interface ProjectSnapshot {
     id: string;
     project: { slug: string; name: string; fingerprint: string };
     revision: { commit: string | null; branch: string | null; dirty: boolean };
     createdAt: string;
     analyzerVersion: string;
     ignoreVersion: string;
     files: FileEntry[];
     languages: LanguageStat[];
     packages: PackageManifest[];
     docs: DocEntry[];
     symbols: SymbolNode[];
     graph: ProjectGraph;
     warnings: AnalysisWarning[];
   }
   ```
2. `FileEntry`: path, language, bytes, hash, line count, isBinary, isGenerated,
   redacted, lastModified.
3. `SymbolNode`: stable ID, kind, name, qualified name, path, range, exported,
   parent ID, decorators, signature summary, documentation summary.
4. `ProjectGraph`: file imports, module edges, approximate symbol references,
   entry points, package boundaries.
5. Snapshot hashing and storage:
   - store under `$SOTHSPELL_HOME/projects/<projectId>/snapshot.json`;
   - write atomically (temp file + rename);
   - never write under the source root.
6. Tests for determinism: analyze the same fixture twice, IDs and hashes match;
   touch a file without content change, snapshot ID stays stable; change content,
   ID changes.

### Wave 2 — TypeScript/JavaScript symbol extraction

1. Use `oxc-parser` (`parseSync`/`parse`) and `oxc-walker` or the exported
   visitor keys. Do not use the TypeScript compiler API.
2. Extract:
   - modules and file-level exports;
   - classes, methods, properties, constructors;
   - functions and arrow functions assigned to names;
   - interfaces, type aliases, enums, namespaces;
   - object literals with named exports;
   - decorators and their arguments (NestJS `@Module`, `@Injectable`,
     `@Controller`, `@Get`, `@Post`, etc.);
   - imports, re-exports, dynamic imports;
   - JSX components and Svelte component references (file-level only for
     Svelte; Bunbun's web app is Svelte).
3. Build stable qualified names:
   `apps/api/src/comments/comments.service.ts#CommentsService.create`.
4. Approximate reference graph:
   - identifier references resolved within the file first;
   - cross-file references resolved by import bindings and exported names;
   - explicitly mark unresolved references; do not guess silently.
5. Framework enrichment:
   - NestJS: modules, controllers, providers, imports/exports, route decorators,
     global filters/interceptors/pipes from `main.ts`.
   - Prisma Next: parse `contract.prisma` for models, fields, and relations;
     link repository/store symbols by name where confident.
   - Package manifests: workspace packages, scripts, dependencies, engines.
6. Tests with fixtures:
   - class + method + constructor;
   - decorators;
   - imports/re-exports;
   - unresolved dynamic import;
   - duplicate symbol names in different files;
   - stable IDs across formatting-only changes where feasible.

### Wave 3 — Project brief and module clusters

1. Deterministic brief:
   - project name and description from `package.json`/README;
   - revision;
   - languages and line counts;
   - top-level directories and package boundaries;
   - entry points (main, app module, CLI bin, web entry);
   - docs index and `CONTEXT.md`;
   - test layout and commands;
   - graph statistics (fan-in/fan-out, cycles, orphans).
2. Module clusters:
   - directory-based clusters with package boundaries respected;
   - cluster labels from directory names, package names, and README headings;
   - a small set of representative symbols per cluster (highest fan-in plus
     entry points).
3. Output a `ProjectBrief` object and a human-readable Markdown summary for the
   CLI and UI.
4. Tests: Bunbun brief detects `apps/api`, `apps/web`,
   `apps/browser-acceptance`, `docs`, and `plans`; the API cluster lists the 21
   feature modules; the web cluster lists the island entry point.

### Wave 4 — Incremental cache and CLI

1. Per-file parse cache keyed by file hash + parser version + options.
2. Snapshot cache keyed by snapshot ID; reuse unchanged file records.
3. Invalidation:
   - content change;
   - ignore-rule change;
   - analyzer version change;
   - framework enrichment version change.
4. CLI:
   ```bash
   pnpm sothspell analyze /path/to/project --json
   pnpm sothspell analyze /path/to/project --brief
   pnpm sothspell analyze /path/to/project --out "$SOTHSPELL_HOME/projects/bunbun/snapshot.json"
   ```
   The CLI writes only to `SOTHSPELL_HOME` or an explicit output path outside
   the source root; it refuses to write inside the source root by default.
5. Progress output and cancellation.
6. Tests: cache hit/miss behavior, cancellation, output path refusal.

## Test seams

Confirm before the first test:

1. `analyzeProject(root, options) → ProjectSnapshot` (analyzer).
2. `ProjectSource` (`listFiles`, `readFile`, `resolvePath`) (source access).
3. `buildProjectBrief(snapshot) → ProjectBrief`.
4. `getSymbol(snapshot, symbolId) → SymbolNode | null` and
   `resolveAnchor(snapshot, anchor) → ResolvedAnchor`.
5. CLI stdout/JSON contract.

What they cover and miss:

- Analyzer: catches parser, path, and determinism failures; misses semantic type
  errors and runtime behavior.
- Source: catches containment and redaction; misses encoding edge cases beyond
  UTF-8.
- Brief: catches missing clusters/entry points; misses narrative quality.
- Symbol resolution: catches drift; misses incorrect but syntactically valid
  references.
- CLI: catches output and write-refusal behavior; misses UI integration.

## Risks and mitigations

- **`oxc-parser` AST differences.** Pin the version and keep the walker behind a
  small adapter; add fixtures for decorators and TS syntax used by Bunbun.
- **Framework coupling.** NestJS/Prisma enrichment lives in separate modules; the
  generic graph remains useful without it.
- **Symlink and path escapes.** Test `realpath` containment and deny devices.
- **Huge repositories.** Enforce file-count and byte budgets; fail with a clear
  message rather than exhausting memory.
- **Generated or vendored files.** Ignore build output and generated Prisma
  artifacts; record the ignore decisions in the snapshot warnings.
- **Svelte parsing.** The first release treats Svelte files as text plus a
  component-level symbol; full Svelte AST parsing is not required for Bunbun's
  island tour.

## Working style

- Sequential. The safety layer lands before parsing.
- Use `tdd` for the analyzer seam and path safety.
- Use `codebase-design` for the `ProjectSource`, `Analyzer`, and enrichment
  boundaries.
- Benchmark the Bunbun run before and after the cache lands; record the numbers.
- Keep every artifact outside the Bunbun tree.

## Shipped (closure, 2026-10-17)

- **Read-only project source** — `.gitignore` files are applied relative to
  their directory, build/vendor/test-report/worktree directories are denied,
  paths are contained by `realpath`, and a symlink escape is refused. Binary and
  large files are recorded and skipped. Secret-like files are hashed, marked
  `redacted`, parsed for symbol names only, and have their signatures,
  decorators, and documentation stripped before the snapshot.
- **Snapshot** — deterministic ID from analyzer/ignore versions, root
  fingerprint, revision, and file manifest. It stores no absolute root and no
  raw source. `--save` writes atomically under
  `$SOTHSPELL_HOME/projects/<slug>/snapshot.json`; `--out` writes outside the
  project; both are covered by tests.
- **Symbols and graph** — `oxc-parser` + `oxc-walker` extract modules, classes,
  methods, properties, functions, variables, interfaces, types, enums,
  namespaces, and objects with stable IDs, decorators, export flags, and parent
  links. The graph resolves TypeScript ESM `.js` specifiers to `.ts` sources,
  records file and package imports, and adds approximate import-based reference
  edges. Prisma models are read from `contract.prisma`/`schema.prisma`.
- **Brief and cache** — `buildProjectBrief` identifies the pnpm workspace,
  applications and entry points, all 21 `apps/api/src` modules, docs, plans,
  Prisma models, and graph statistics. A per-file cache keyed by analyzer
  version, path, language, content hash, and redaction state makes warm runs
  cheap.
- **CLI** — `sothspell analyze <path>` with `--json`, `--brief`, `--out`,
  `--save`, `--no-cache`, and `--help`; exit codes distinguish usage, analysis,
  and write failures. The root `pnpm sothspell` script runs it.
- **Bunbun acceptance** — 642 files, 10,040 symbols, 1,588 file imports, 822
  package imports, 2,178 reference edges, 21 feature modules, 25 Prisma models.
  All ten key symbols resolve; all 20 golden-tour anchors resolve with matching
  hashes; the Bunbun worktree is unchanged.

### Deviations from the plan

- The first CLI release covers `analyze` only; `author`, `serve`, and `doctor`
  land with their phases. The CLI's `--save` path is the snapshot store; the API
  will consume the same files in Phase 3.
- NestJS and Prisma enrichment is structural: decorators and model names/fields
  are captured, but DI graph reconstruction and framework-specific route
  inventories are left to the authoring context pack.
- Cross-file references are import-based and conservative (`confidence:
'import'`), not full type resolution. Full type semantics would require the
  TypeScript compiler API that TS 7.0 does not ship.
